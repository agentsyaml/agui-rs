# upstream-spec

Verbatim copies of the wire-level protocol artifacts from the upstream
`ag-ui-protocol/ag-ui` repository. These files are the **reference for wire
compatibility** of this crate's `src/schema.rs`; nothing here is ours to edit.

**Source commit: `024332cbb71e03e6a6bc055bed5af9c5c504471a`**
(Merge pull request #2846 from ag-ui-protocol/fix/connect-read-only-interrupt-validation)

This repository's protocol alignment target is upstream **`ag-ui` 1.0.0**; these
files are its `spec/1.0/` artifacts.

## Which file is the source of truth

- **`schema.json` is the only hand-written source.** It is the single place the
  protocol shape is authored.
- **Everything else here is generated**, including all three `.proto` files.
  Each carries a `@generated by spec/generator — DO NOT EDIT` header and
  regenerates with `pnpm --filter @ag-ui/spec generate`. Do not patch a `.proto`
  by hand and do not "fix" formatting.
- **`proto-freeze.txt` is the source of truth for wire numbers.** It is an
  append-only table of every field slot the binary transport has ever shipped.
  The generator assigns the next free number to a new slot and writes it here; a
  slot whose schema field is gone becomes a reserved number. Nobody authors a
  number by hand. Field numbers in the `.proto` files come from this file, so
  when checking a number, check it against `proto-freeze.txt`.

## Why these are vendored

A previous round of protocol alignment in this repo was done against
`raw.githubusercontent.com` content that turned out to be a **stale cache** — it
predated the upstream 1.0.0 release, where the `.proto` files were still
hand-written rather than generated. The result was alignment to 0.0.5x
semantics. The root cause was not pinning the commit being read.

Vendoring removes the failure mode: the bytes are in-tree, reviewed in the diff,
and tied to an explicit commit and blob SHA above. Never re-derive these files
from a network fetch.

## Updating to a new upstream commit

1. Check out / fetch the new upstream commit locally.
2. Re-extract each file by blob, keeping the content byte-for-byte (e.g.
   `git -C <upstream> rev-parse <commit>:<path>` then
   `git -C <upstream> cat-file -p <blob> > <dest>`), and verify the result.
3. Update the commit and blob SHAs in the table above, in this file and in the
   header comment of `src/schema.rs`.
4. Only then update `src/schema.rs`.

To verify a vendored file is still byte-identical to its recorded blob:

```sh
git hash-object crates/agui-rs-proto/upstream-spec/events.proto
# must equal the blob SHA in the table
```

## Consistency with `src/schema.rs`

`src/schema.rs` is a hand-written Rust mirror of the generated artifacts in this
directory. It is not generated — this crate has no `protoc` build-time
dependency, so the mapping is maintained by hand. That makes drift possible and
is the reason the conformance test suite is the thing that actually guards it.

Consistency is guaranteed by `crates/agui-rs-proto/tests/proto_drift.rs`. It
parses the files in this directory and compares them against `src/schema.rs` —
message names, field names, field numbers, wire types, `repeated`, `oneof` tags
and enum values — so a renumbering on either side fails the build. Neither side
is a hardcoded expectation list: the actual side is a parse of these `.proto`
files, the expected side is a parse of `src/schema.rs`'s own `#[prost(...)]`
attributes. `tests/round_trip.rs` anchors that to the wire with literal expected
bytes, since prost 0.13 has no runtime reflection to compare against.

When that suite flags a mismatch, the upstream files in this directory are the
arbiter — not the Rust code, and not a cached web copy.
